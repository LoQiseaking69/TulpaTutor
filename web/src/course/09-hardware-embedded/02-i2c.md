**I2C** is a two-wire bus used by most small sensors: IMUs, temperature sensors, ADCs,
displays. Each device has a 7-bit **address**, and inside it a map of **registers**, numbered
bytes you read and write.

## Opening a device and reading a register

```tulpa
let imu = I2C::new(1, 0x68)              # bus 1, address 0x68
sim::i2c_set(0x68, 0x75, [0x68])         # simulator: preload WHO_AM_I
let who = imu.read_reg(0x75)
print("WHO_AM_I =", hex(who), if who == 0x68 { "(MPU-6050 found)" } else { "(unknown)" })
```

Reading an identity register first is how every driver checks it is talking to the right
chip.

## Writing registers

```tulpa
let imu = I2C::new(1, 0x68)
imu.write_reg(0x6B, 0x00)                # PWR_MGMT_1: wake up
imu.write_reg(0x1C, 0x10)                # ACCEL_CONFIG: ±8 g
print(sim::i2c_get(0x68, 0x6B, 1), sim::i2c_get(0x68, 0x1C, 1))
```

`sim::i2c_get(addr, reg, n)` lets a test inspect what the program wrote.

## Read-modify-write

Often you must change some bits of a register and leave the rest. `update_reg(reg, mask,
value)` does it in one call:

```tulpa
let dev = I2C::new(1, 0x48)
sim::i2c_set(0x48, 0x01, [0b1010_0011])
dev.update_reg(0x01, 0b0110_0000, 0b0100_0000)    # set a 2-bit field to 0b10
print(bin(dev.read_reg(0x01)))
```

## Multi-byte values

Sensors report 16-bit values across two registers. `read_u16` and `read_i16` read a
big-endian pair (pass `"little"` for little-endian parts); `read_regs` bursts several:

```tulpa
let tmp = I2C::new(1, 0x48)
sim::i2c_set(0x48, 0x00, [0x19, 0x00])
let raw = tmp.read_u16(0x00)
print("raw:", raw, "->", (raw >> 4) * 0.0625, "degC")

let imu = I2C::new(1, 0x68)
sim::i2c_set(0x68, 0x3B, [0x00, 0x10, 0xFF, 0xF0, 0x40, 0x00])
let b = imu.read_regs(0x3B, 6)
let g = [0, 2, 4].map(|i| round(int_from_bytes(b[i..i + 2], "big", true) / 16384.0, 3))
print("accel (g):", g)
```

All of these use a single transaction with a **repeated start**, which is what most sensors
expect.

## A tiny driver

Wrap the register details in a struct with a meaningful API and units:

```tulpa
const TEMP_REG = 0x00
struct Tmp102 {
    bus: I2C
    fn temperature(self) -> [K] {
        let raw = self.bus.read_u16(TEMP_REG) >> 4
        let c = if raw >= 0x800 { raw - 0x1000 } else { raw }   # 12-bit signed
        273.15[K] + c * 0.0625[K]
    }
}
let sensor = Tmp102(I2C::new(1, 0x48))
sim::i2c_set(0x48, 0x00, [0x19, 0x60])     # 25.375 degC
print(sensor.temperature())
sim::i2c_set(0x48, 0x00, [0xFF, 0x00])     # -1 degC
print(sensor.temperature())
```

```quiz
? Why do drivers read a WHO_AM_I register first?
+ to confirm the expected chip is at that address
- to wake the chip up
> It is the identity check.
? Which call changes only the masked bits of a register?
- `write_reg`
+ `update_reg(reg, mask, value)`
> Read-modify-write in one call.
```

:::exercise Pressure sensor
A barometer at address `0x77` stores pressure in pascals as an unsigned 24-bit big-endian
value in registers `0xF7, 0xF8, 0xF9`. Preload `[0x01, 0x8B, 0xCD]`, read the 3 bytes with
`read_regs`, combine them, and print the pressure as a `[Pa]` quantity converted to `kPa`
with 2 decimals (f-string).

Expected: `101.33 kPa`

```tulpa starter
let baro = I2C::new(1, 0x77)
sim::i2c_set(0x77, 0xF7, [0x01, 0x8B, 0xCD])
```
```tulpa solution
let baro = I2C::new(1, 0x77)
sim::i2c_set(0x77, 0xF7, [0x01, 0x8B, 0xCD])
let b = baro.read_regs(0xF7, 3)
let pa = (b[0] << 16) | (b[1] << 8) | b[2]
let p = pa * 1[Pa]
print(f"{p.to("kPa"):.2f}")
```
```expect
101.33 kPa
```
```hint
`(b[0] << 16) | (b[1] << 8) | b[2]` combines three bytes; `0x018BCD` is 101325.
---
Make it a quantity with `* 1[Pa]` and convert with `.to("kPa")`.
:::

:::takeaways
- `I2C::new(bus, addr)`: `read_reg write_reg update_reg read_regs read_u16 read_i16`.
- `sim::i2c_set` preloads registers, `sim::i2c_get` inspects writes.
- Wrap register maps in structs that return quantities.
:::
